PROBLEM DESCRIPTION
───────────────────────────────────────────────────────────────────────────
When adding/removing tracks from a GPX file using PyGuitarPro, the library
produced internally inconsistent files:

  score.gpif          ✅ Correctly showed all tracks
  misc.xml            ❌ Wrong PreferredTrackCount
  PartConfiguration   ❌ Wrong binary data
  LayoutConfiguration ❌ Wrong binary data

Result: Guitar Pro opened the file but only displayed SOME tracks.


ROOT CAUSE
───────────────────────────────────────────────────────────────────────────
In src/guitarpro/gp6.py, GP6File.writeSong():
  1. Generated fresh score.gpif XML ✅
  2. Blindly copied all container files from source ❌

No code existed to regenerate container metadata when tracks changed.


THE FIX
───────────────────────────────────────────────────────────────────────────
Created: src/guitarpro/gp6_container_metadata.py
  → Functions to generate misc.xml, PartConfiguration, LayoutConfiguration
  → Binary formats reverse-engineered from Guitar Pro files
  
Modified: src/guitarpro/gp6.py
  → GP6File.writeSong() now auto-updates metadata before writing


USER IMPACT
───────────────────────────────────────────────────────────────────────────
BEFORE (90 lines of manual workaround):
  main_song = gp.parse('one_track.gpx')
  ref_song = gp.parse('two_track_reference.gpx')
  
  # Manual metadata copying - error-prone!
  copy_two_track_container_metadata(main_song, ref_song)
  
  main_song.tracks.append(new_track)
  gp.write(main_song, 'output.gpx')

AFTER (automatic - 3 lines):
  main_song = gp.parse('one_track.gpx')
  main_song.tracks.append(new_track)
  gp.write(main_song, 'output.gpx')  ← Metadata auto-updated!
